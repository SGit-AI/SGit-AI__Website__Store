# post-purchase · V4

A embeds the vault full-width after a receipt strip; B uses a receipt rail; C puts the vault first. Every variant calls the displayed vault an example in its first sentence. The interactive local shell uses supplied aggregate counts, not a live personal vault. File contents, download hash/size, provider receipt, real dates and assigned professional are absent and labelled. Level buttons demonstrate the four return states. Runtime date arithmetic uses payment/reply timestamps only if they exist; otherwise date is a placeholder. The printable receipt is a sample, not proof of payment.

## Validation boundary

Plain HTML/CSS/JavaScript; no build required. Static checks cover local routes, form prohibition, manifest coverage, source data and script syntax. Browser visual QA is not claimed.
