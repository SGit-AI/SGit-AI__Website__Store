How this works

Each review keeps its own stance on every proposal in it — do now, do next, won’t do, or needs a ruling — and carries a verdict control so the reviewer can disagree with the stance and say why. The reasons matter more than the verdicts; the whole point of writing down a won’t do is that somebody gets to argue with it.

Adding one is adding a file. A review is a JSON record in data/reviews/ and a line in the register; the page, its markdown twin, its card here and its place in the sort are generated. The build refuses a register entry with no file and a file with no register entry, because a review nobody can reach is a review that did not happen.
